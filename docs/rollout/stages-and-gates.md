# 점진적 전환 단계와 승격 판단

- API별 전환 단계 유지
- 사용자·계약·관측·자원·복귀 증거에 근거한 다음 비율 결정

## 기능 계약

| 항목 | 정의 |
| --- | --- |
| 시작 조건·입력 | 현재 stage·epoch·revision, G-01~G-08 증거, 다음 단계와 목표 비율 |
| 결과·출력 | 유지·확대·보류 판단과 적용할 변경 의도 |
| 실패·제한 | 필수 gate의 fail·unknown이면 확대 금지, 대상 API의 전체 v2 응답과 전체 서비스 종료 구분 |

## 운영 단위

- 전환 단위: 등록 route 또는 호환된 cohort group
- 단위별 기록: 담당자, 현재 stage, 설정 revision, 비교 policy revision, 관측 epoch, 마지막 유효 복귀 설정

- 같은 stage에서도 비율·정책·backend 배포 변경 시 관측 조건 재평가
- 변경 시점과 전파 구간 기록, 새 조건의 최소 표본·관측 기간 확보
- 배포 완료와 제품 gate 통과의 별도 기록
- 독립 데이터 원천 사용 시 초기 적재·변경분 반영·삭제·최신성 준비를 외부 선행 조건으로 확인; 프록시 자체에 데이터 동기화 단계 추가 금지

## 단계별 상태

| 단계 | 사용자 응답 | shadow | 진입·완료 조건 | 복귀 방식 |
| --- | --- | --- | --- | --- |
| S0 BASELINE | 기존 v1 직접 경로 | 없음 | 대상 계약·부작용·현재 오류·지연·트래픽 파악 | 기존 경로 유지 |
| S1 V1_ONLY | 프록시를 통한 v1 | 0 | 프록시 추가 영향, 인증·헤더·오류·우회 검증 | 기존 v1 직접 경로 |
| S2 SHADOW | v1 | 작은 비율에서 필요한 수준까지 | 같은 요청 비교, 양쪽 오류·부하, 수집 완료율 검증 | shadow 중지 |
| S3 CANARY | 일부 v2 | 검증 목적에 맞게 유지 | 실제 사용자 영향, 배정 일관성, v1 복귀 검증 | v2 응답 비율 0 |
| S4 V2_PRIMARY | 전체 v2 | 필요 시 v1 shadow 유지 | 전체 serving 부하·주요 업무 주기, v1 복귀 준비 | v1 조건 확인 후 비율 0 |
| S5 SHADOW_OFF | 전체 v2 | 0 | v2 단독 부하, v1 cold 상태 복귀 조건 재평가 | 준비된 v1 재사용 또는 재가동 절차 |
| S6 RETIRED | v2 직접 경로 | 없음 | 잔존 v1 의존 제거, 프록시 우회·제거 검증, 보존 종료 정책 | 별도 배포·복구 절차 |

- S3 비율 예시: 1% → 5% → 25% → 50%
- 실제 비율·유지 기간: 요청량, 위험도, 표본 확보, 복귀 능력에 따라 결정
- 특정 비율 도달만으로 성공 판정 금지

- S4 전체 v2의 범위: 해당 전환 대상에 한정
- 미등록 경로·미지원 프로토콜·쓰기·배치의 v1 의존 잔존 시 v1 전체 종료 불가
- S4 이후 동시 v1 serving 대조군 부재: 이전 canary 비교 증거와 현재 전체 serving SLO·업무 주기 검증을 구분

## 첫 대상의 준비 목록

- method·path·입출력·성공·예상 거절·업무 오류와 호환 기준 문서화
- 조회수·cache·외부 호출·quota를 포함한 양쪽 실행의 효과 확인
- v1/v2의 데이터 원천·스키마·동기화·권한·세션 관계 확인
- QPS·응답 크기·현재 지연·오류의 대표 분포와 피크 구간 확보
- 비교 필드·제외 규칙·문맥 허용치·수집 허용 필드·보존 기간 결정
- 사용자 SLO, 비교 완료율·표본 조건, 자원·비용 예산 결정
- 변경 담당자와 실제 적용·중지·복귀 수단 확인
- 프록시 장애 시 v1 직접 경로와 실제 복구 시간 검증

## 승격 gate

- gate 결과: `pass`, `fail`, `unknown`
- 필수 gate 중 fail 또는 unknown 존재 시 다음 stage 확대 금지
- unknown의 의미: 판단 근거 미확보; 0 오류·통과로 치환 금지
- 적용 대상이 아닌 검사는 적용 제외 사유·대체 증거 기록; 미실행 검사를 pass로 기록 금지

| Gate | 확인 내용 | 필요한 증거 |
| --- | --- | --- |
| G-01 계약 | 공개 API 계약과 중요 업무 불변식 유지 | contract fixture·차이 사례·의도적 변경 목록 |
| G-02 사용자 품질 | 오류·지연이 기준 내에 있음 | 동일 epoch의 serving 지표와 기준선 |
| G-03 비교 신뢰도 | 표본·완료율·제외·드롭이 기준 충족 | E/S/D/T/C/W 및 result·reason별 지표 |
| G-04 자원·비용 | 양쪽 실행·capture·저장이 예산 내에 있음 | backend QPS, inflight, 메모리·큐·저장·비용 추정 |
| G-05 데이터·권한 | 같은 의미의 데이터·권한으로 동작 | source 관계·freshness·스키마·테넌트 검증 |
| G-06 복귀 | v1과 이전 설정이 실제 복귀 가능 | v1 최신성·용량·계약, 복귀 연습과 소요 시간 |
| G-07 적용 상태 | 모든 대상 인스턴스와 설정을 독립적으로 읽는 worker의 신규 요청용 revision이 의도한 값과 일치 | [설정 적용 현황](../routing/configuration.md)·실제 serving 분포 |
| G-08 관측 기간 | 업무 피크·배치·주기와 최소 표본 포함 | 관측 시작·종료, 대표 구간과 누락 구간 설명 |

## 단계별 증거 적용

| 구간 | 비교 증거 | 필수 확인 |
| --- | --- | --- |
| S0~S1 비교 미실행 | G-03 비교 결과 판단 제외 사유 기록 | 기준선·메트릭 경로·프록시 추가 영향 검증 |
| S2~S4 비교 실행 구간 | 해당 epoch의 실제 비교 분모·완료율·제외·드롭 | 최소 표본·기간과 사용자·복귀 gate 함께 확인 |
| S5 shadow 중지 | 신규 shadow 선택 S=0, 적격 요청 E는 계속 집계; 마지막 유효 비교 증거의 revision·기간 보존 | 잔여 비교·저장 작업과 현재 serving·수집 상태, v1 cold 상태와 복귀 시간 재검증 |
| S6 프록시 제거 | 프록시 비교의 종료 기록 | 직접 v2 경로 관측·잔존 의존·데이터 복구 수단 검증 |

- S5의 S=0: 계획된 비교 종료 상태, 비교 실행 중 메트릭 유실과 구분
- 중지 이전 요청의 D·T·C·W: 잔여 실행·비교·저장이 끝날 때까지 증가 가능, 해당 요청의 기존 epoch에 귀속
- S4에서 이미 v1 shadow를 중지하는 경우에도 S5의 종료·복귀 준비 검증 적용
- shadow 종료 후 backend·공개 계약·데이터 문맥 변경 시 과거 비교 증거의 유효성 재평가; 필요 검증 미충족 시 종료 보류
- 전체 적격 요청의 양쪽 실행을 검증 목표로 선택한 경우 `shadow_sample_ratio=1` 외에 실제 선택·dispatch·종료·timeout·cancel·drop 확인
- 보호 상한·취소·드롭으로 실행이 줄어든 구간: 전체 목표 부하 검증 완료로 인정 금지
- 일부 shadow 표본만 검증한 경우: 검증한 부하 범위 명시, 전체 v2 serving 용량 증거 별도 확보
