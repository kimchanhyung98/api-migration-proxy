# 마이그레이션 종료와 프록시 제거

- 전체 v2 전환 후 잔존 v1 의존·복귀 기간·보존 기간 정리
- 직접 v2 호출의 공개 계약과 운영 상태 검증

## 기능 계약

| 항목 | 정의 |
| --- | --- |
| 시작 조건·입력 | v2 전체 serving 증거, v1 잔존 호출자·업무 주기·복귀 기간, 직접 연결 경로 |
| 결과·출력 | shadow 종료·v1 정리·프록시 제거의 각각의 완료 기록 |
| 실패·제한 | 미등록 경로·batch·세션 잔존 시 전체 종료 금지, shadow 종료와 데이터 동기화 중지의 별도 판단 |

## 종료 체크

1. 전환 대상의 v2 전체 serving이 주요 업무 주기·피크의 기준을 충족하는지 확인
2. v1을 사용하는 미등록 API·batch·관리자 도구·내부 client·세션의 잔존 여부 조사
3. v1 shadow 종료 전후 부하·cache·지연 변화와 v1 재가동·warm-up 복귀 시간 확인
4. v2 직접 호출의 인증·헤더·DNS·네트워크·오류 처리 계약 확인
5. 프록시 trace·계측·경로 매핑에 대한 호출자 의존과 직접 경로의 관측 수단 확인
6. 복귀 기간·서비스와 데이터 복구 수단 검토 후 v1 종료와 프록시 제거를 별도 변경으로 수행
7. 비교 이벤트·상세 표본·설정 변경 이력의 보존·만료 담당·기한 확정; 기한 도래 데이터만 정리
8. 최종 결과·실제 추가 비용·남은 한계 기록

## 종료 결과 구분

| 결과 | 완료 증거 |
| --- | --- |
| v1 shadow 종료 | 실제 반대편 실행량과 v2 단독 사용자 지표 |
| v1 사용 종료 | 미등록·관리·배치·내부 client를 포함한 잔존 호출 점검 |
| 프록시 제거 | 직접 v2 호출의 인증·헤더·오류·연결 계약 검증 |
| 관측 기록 정리 | 목적별 보존·만료 담당·기한, 기한 도래 데이터의 정리 결과, 전환 결과 보고 |

- 종료 후 복귀: 배포·데이터 복구가 필요한 경계와 남은 복구 수단 기록
- 데이터 동기화 중지·원본 로그 만료·v1 리소스 제거의 시점 구분
- 복귀에 필요한 원본·백업의 보존 종료 전 담당 서비스의 복구 가능성 확인
- 관측 기록의 보존 기간이 남은 경우 서비스 종료만을 이유로 조기 삭제 금지
