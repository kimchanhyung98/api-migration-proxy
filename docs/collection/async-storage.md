# 비동기 적재·재시도·유실 처리

- 사용자 응답과 분리된 제한 큐에서 비교·마스킹·저장 수행
- 저장 장애의 사용자 경로 영향 제한

## 기능 계약

| 항목 | 정의 |
| --- | --- |
| 시작 조건·입력 | backend 실행 결과·사용자 응답 전송 종료 결과와 제한된 캡처, 큐·batch·시간·저장 재시도 예산 |
| 결과·출력 | 저장된 고유 이벤트, queue age·저장 지연·실패·드롭 계측 |
| 실패·제한 | 프로세스 메모리 큐의 무손실 보존 보장 불가, 저장 장애로 인한 serving 동기 대기 금지 |

## 수집 생명주기

1. 최소 실행 메타데이터·제한된 캡처 수집
2. serving backend 종료, shadow 종료 또는 미실행, 사용자 응답 전송 종료·실패를 모두 확정한 뒤 비교 큐 제출; shadow deadline이나 backend 수신 완료만으로 사용자 종료 결과의 조기 확정 금지
3. 비교 정책 적용 후 저장 허용 필드만 유지
4. 제한된 batch로 요약 저장, 일시적 저장 오류의 횟수·시간 제한 재시도
5. 저장 실패·ACK 미확인·감지된 드롭·queue age의 독립 계측
6. 만료된 상세·요약 삭제, 삭제 실패·적체 확인

- 선택된 shadow의 미실행: serving backend와 사용자 응답 전송의 종료 결과를 확보하여 `not_executed` 요약 생성 시도
- 큐 대기·비교·마스킹·저장 재시도를 모두 수집 작업의 최대 수명에 포함
- 비동기 큐의 한계: 같은 event loop에서 수행하는 동기 파싱·비교·마스킹의 CPU 격리나 선점 중단을 보장하지 않음. [Python asyncio 실행 지침](https://docs.python.org/3/library/asyncio-dev.html#running-blocking-code)
- 실행 위치 선택: 허용 최대 입력량·복잡도의 동시 처리와 연속 취소 부하에서 serving 지연·남은 작업·메모리 상한 검증; 별도 process·worker는 해당 예산을 만족하는 데 필요한 경우에만 검토
- 프로세스 강제 종료 시 메모리 이벤트 유실 가능
- 마지막 유실 개수 확인 불가 구간: 관측 완전성 미확인 표시
- 모든 관측의 보존 필수 요구 발생 시: 내구성 기록 경로·내부 큐 수명·사용자 응답 대기 계약 재검토

## 적재 상태와 재시도 경계

| 상태 | 다음 동작 | 남길 증거 |
| --- | --- | --- |
| 큐 제출 성공 | 최대 수명 안에서 비교·마스킹 후 배치 | 제출·처리 시각과 대기 시간 |
| 큐 포화·만료 | 이벤트를 버리고 serving 계속 | 감지된 드롭 이유와 개수 |
| 저장 성공 | 고유 event ID의 저장 완료로 집계 | 저장 확인 시각 |
| 일시적 저장 실패 | 정한 시간·횟수 안에서 같은 event ID로 재시도 | 저장 실패와 재시도 소진 여부 |
| 저장 성공 여부 불명 | 같은 event ID로 재확인 또는 중복 방지 재시도 | 확인 전 ACK 미확인 유지, 동일 이벤트의 중복 성공 집계 금지 |
| 배치 일부 성공 | 고유 ID별 확정 성공·실패·미확인 분리 | 재시도 시 성공 행 중복 생성 방지 |
| 비교·마스킹 작업 오류 | 안전한 요약 생성 가능 여부 확인, 불가 시 드롭 | backend 실행 오류와 수집 작업 오류의 분리 |
| 프로세스 강제 종료 | 유실 가능 구간을 보고 | 완전성 미확인과 복구 이후 적체 |

- 배치 재시도 중 신규 논리 이벤트 생성 금지
- 저장 실패 횟수와 최종 드롭 이벤트 수 구분; 같은 이벤트 재시도를 복수 유실로 집계 금지
- ACK 미확인 상태에서 재시도 예산 소진: 로컬 작업 종료 사실과 실제 저장 유무 미확인 상태를 함께 기록
- 실제 저장소에 행이 남을 수 있는 ACK 미확인을 확정 데이터 손실로 단정 금지
- 정확한 마지막 유실 개수 확인 불가 시 0 채우기 금지
