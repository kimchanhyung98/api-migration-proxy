# 상세 표본 선택과 데이터 마스킹

- 요약 비교를 유지하며 조사에 필요한 상세만 제한된 표본으로 저장

## 기능 계약

| 항목 | 정의 |
| --- | --- |
| 시작 조건·입력 | 상세 표본율, 허용 필드·bytes 상한, 마스킹·보존 정책과 비교 결과 |
| 결과·출력 | 허용된 상세 표본 또는 요약만 남긴 이벤트 |
| 실패·제한 | token·cookie·민감 예외·허용되지 않은 diff 값의 저장 금지, 편향된 상세 표본의 전체 차이율 사용 금지 |

## 요약·상세·민감 정보

| 구분 | 기본 제안 |
| --- | --- |
| 메트릭 | 전 요청에 대해 가능한 범위에서 집계. 원문 사용자·query를 label로 사용하지 않음 |
| 비교 요약 | 선택된 shadow 요청의 결과와 차이 경로 중심 |
| 상세 표본 | 기본 비활성. 필요 시 허용 필드와 최대 크기를 정한 일부 사례만 저장 |
| 인증·비밀 | Authorization, cookie 값, API key, 서명, credential 포함 URL 저장 금지 |
| 검색어·업무 원문 | 요약 기본 필드에 포함하지 않음. 필요성과 보존·조회 권한을 먼저 결정 |
| 개인정보 hash | 자동 익명화로 간주하지 않음. 원문 대신 hash를 저장할 이유도 검토 |

- 조사용 편향 표본을 전체 불일치율 계산에 사용 금지
- 파일 이름·예외 메시지·diff 값에도 동일한 마스킹 규칙 적용

## 선택과 마스킹 순서

1. 상세 저장 여부와 독립적인 실행·비교 판정 확정
2. route의 상세 수집 허용 여부 확인 및 표본 선택
3. 허용 필드·bytes 상한 적용, 불일치 우선 표본에도 전체 cap 적용
4. 인증·개인정보·예외·diff·객체 키의 민감 값 제거
5. 마스킹 실패 시 상세 저장 중지 및 사유 계측, 안전하게 생성된 요약 유지
6. 표본 선택 여부·상세 상태·만료 기준 기록

- 비교 필수 필드의 저장 정책을 이유로 한 자동 비교 제외 금지
- 허용된 메모리 비교와 저장 값의 경계 구분
- 기본 `detail_sample_ratio=0`: 상세만 비활성화, 요약·비교·메트릭 유지
- 마스킹 전 원문: 허용된 메모리 범위에서만 처리, 실패 로그·임시 파일·원문 재시도 큐로 전송 금지
- 자동 HTTP 계측: 상세 표본율과 별도로 URL·query·header·exception에 같은 허용 정책 적용; exporter 전달 전 금지 값 제거를 실제 전송 데이터로 검증
- [OpenTelemetry 민감정보 처리](https://opentelemetry.io/docs/security/handling-sensitive-data/) 기준의 수집 최소화 적용; 상세 표본율 0만으로 자동 계측의 민감정보 수집 차단을 가정하지 않음

## 상세 상태 구분

| 상태 | 의미 |
| --- | --- |
| 비활성·미선택 | 상세 정책 비활성 또는 표본 선택 제외 |
| 선택·대기 | 상세 표본 선택 후 안전한 내용 생성·저장 대기 |
| 저장 완료 | 허용된 상세 저장 확인 |
| 마스킹 실패·상한 초과·저장 미확인 | 선택됐으나 상세 확보 미완료, 개별 이유 유지 |
| 만료 | 보존 정책에 따른 상세 삭제, 현재 조회 시 계산 가능한 상태 |

- 표본 선택 여부와 실제 상세 저장 여부의 분리
- 상세 없음·마스킹 실패·만료를 빈 원문 정상 수집으로 표현 금지
