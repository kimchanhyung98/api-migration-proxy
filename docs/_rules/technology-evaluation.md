# 기술 자료 적용과 검증 기준

이 문서는 외부 기술 자료를 제품의 기능 설계와 구현 선택에 적용하는 절차를 정의한다. 외부 제품이 기능을 지원한다는 사실, 이 프로젝트가 그 기능을 채택했다는 결정과 실제 환경에서 검증한 결과를 구분한다.

## 자료의 적용 범위

| 확인 항목 | 확인할 내용 | 허용하지 않는 해석 |
| --- | --- | --- |
| 제품·버전 | 자료가 설명하는 제품과 버전을 식별하고, 채택 대상 버전의 지원 범위와 대조한다. | 유사한 제품이나 다른 버전도 같은 기능을 지원한다고 추정해서는 안 된다. |
| 프로토콜·환경 | 설명된 기능의 프로토콜, 실행 방식과 환경 제약을 확인한다. | 다른 프로토콜이나 실행 환경에서 같은 동작을 보장한다고 해석해서는 안 된다. |
| 문서 기준점 | `latest`나 기본 브랜치의 문서는 채택 버전의 설정·기능과 대조한다. | 현재 웹 문서의 예제가 설치된 버전에 그대로 적용된다고 가정해서는 안 된다. |
| 서비스 이용 조건 | 선택 또는 업그레이드 시점에 계정·리전의 이용 가능성과 유지보수·지원 상태를 확인한다. | 과거에 이용할 수 있었다는 사실만으로 현재 이용 가능하다고 판단해서는 안 된다. |
| 성능 수치 | 공식 예제나 외부 사례가 사용한 요청, 자원과 측정 조건을 확인한다. | 외부 수치를 대상 API의 성능 보장이나 운영 목표로 직접 대입해서는 안 된다. |

확인하지 못한 항목은 미확인으로 기록한다. 자료에 설명이 없다는 사실과 해당 기능을 지원하지 않는다는 사실은 같지 않다.

## 증거의 구분

| 구분 | 판단할 질문 | 필요한 확인 |
| --- | --- | --- |
| 설계 적합성 | 후보의 지원 기능이 serving, shadow, 비교와 수집의 계약을 충족하는가? | 지원 범위와 제약을 기능 계약의 각 조건에 대응시킨다. |
| 구현 동작 | 채택한 구성에서 요구한 처리가 수행되는가? | HTTP 전달, 취소, timeout, 연결 정리와 저장 ACK를 해당 요청 및 실패 조건에서 확인한다. |
| 운영 적용 | 대상 환경에서 허용한 부하와 복구 조건을 충족하는가? | 대표 부하, 설정 전파, 데이터 문맥, 복귀와 배포 종료 조건을 확인한다. |

한 구분의 증거만으로 다른 구분을 통과 처리해서는 안 된다. 예를 들어 지원 기능이 설계와 일치해도 대상 환경의 부하나 복귀가 검증된 것은 아니다. 각 확인의 입력, 범위, 결과와 미확인 사항은 [부하 시험과 검증 증거](../validation/load-and-evidence.md)의 기준에 따라 기록한다.

## 기술 선택 절차

이 절차는 실행 구성이나 외부 제품을 선택하거나 변경할 때 적용한다. API 개발자는 대상 API의 계약을 제공하고, 운영 담당자는 기존 gateway와 실행 환경의 제약을 제공한다. API 개발자와 운영 담당자는 두 조건을 대조하여 선택 근거를 기록한다.

1. **대상 API의 계약을 확보하십시오.** 확인 대상은 요청·응답, 부수 효과, 권한과 데이터 조건입니다.
2. **평가 기준의 누락 여부를 확인하십시오.** 기준으로 사용할 계약이 불명확하면 후보 평가를 보류하십시오.
3. **기존 실행 조건을 확인하십시오.** 확인 대상은 기존 gateway, 배포 환경과 채택 대상 제품·버전의 설정입니다.
4. **후보의 지원 범위를 대조하십시오.** 대상 API의 계약과 기존 실행 조건을 모두 사용하십시오.
5. **필요한 계약을 충족하는 최소 구성을 선택하십시오.** [프록시 도구 비교](../research/proxy-patterns-and-tools.md)와 [실행 구조](../infrastructure/deployment-and-stack.md)의 적용 조건을 사용하십시오.
6. **선택 근거와 지원 한계를 기록하십시오.** 지원하지 않는 기능과 추가 구현이 필요한 책임을 구분하십시오.
7. **선택한 구성의 동작을 확인하십시오.** 입력과 응답을 제어할 수 있는 합성 backend를 사용하십시오. 확인 대상은 양쪽 실행, 사용자 응답 보존과 수집 장애 처리입니다.
8. **동작 확인 결과를 기록하십시오.** 결과가 요구사항을 충족하지 않으면 실패로 기록하십시오. 결과를 확인하지 못했으면 미확인으로 기록하십시오.
9. **운영 적용의 증거를 확인하십시오.** 확인 대상은 대표 부하, 실제 데이터 문맥과 복귀 조건입니다.
10. **해당 전환 gate를 판단하십시오.** 구현 동작의 확인만으로 운영 gate를 통과 처리하지 마십시오.

기술 선택의 완료는 선택한 제품·버전, 적용 범위, 근거와 남는 제약을 식별할 수 있는 상태이다. 운영 적용의 완료는 해당 환경의 gate를 충족한 상태이다. 두 완료 상태를 같은 의미로 사용해서는 안 된다.
