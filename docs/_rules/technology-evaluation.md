# 기술 자료 적용과 검증 기준

- 목적: 외부 기술 자료를 기능 설계·구현 선택에 적용하는 기준 정의
- 외부 제품의 지원 기능과 이 프로젝트의 구현·운영 검증 결과 구분

## 자료의 적용 범위

- 제품·버전·프로토콜·실행 환경별 지원 범위 확인; 유사 제품이나 다른 실행 환경으로 일반화 금지
- `latest`·기본 브랜치 문서: 실제 채택 버전의 설정·지원 범위와 대조
- 서비스 선택·업그레이드 시: 계정·리전 이용 가능성, 유지보수·지원 상태 재확인
- 공식 예제·외부 사례의 성능 수치: 대상 API의 성능 보장이나 운영 목표로 직접 대입 금지

## 검증 기준

- 설계: 지원 기능이 serving·shadow·비교·수집 계약을 충족하는지 검토
- 구현: HTTP 전달·취소·timeout·연결 정리·저장 ACK를 실제 요청과 실패 조건으로 확인
- 운영: 대표 부하·설정 전파·데이터 문맥·복귀·배포 종료 조건을 실제 환경에서 확인
- 검증 계층별 범위와 결과 기록: [부하 시험과 검증 증거](../validation/load-and-evidence.md)

## 기술 선택 절차

1. 대상 API의 요청·응답·부수 효과·권한·데이터 계약 확보
2. 기존 gateway·배포 환경과 제품·버전의 설정 확인
3. [프록시 도구 비교](../research/proxy-patterns-and-tools.md)와 [실행 구조](../infrastructure/deployment-and-stack.md)의 조건을 대조하여 최소 구성 선택
4. 합성 backend로 양쪽 실행·응답 보존·수집 장애의 최소 흐름 검증
5. 대표 부하·실제 데이터·복귀 시험 이후 운영 gate 판단
