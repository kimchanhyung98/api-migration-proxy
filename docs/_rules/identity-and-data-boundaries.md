# 인증·권한과 데이터 동기화 책임

- 같은 논리 요청의 권한 의미 보존
- 프록시와 서비스·데이터 계층의 책임 구분

## 기능 계약

| 항목 | 정의 |
| --- | --- |
| 시작 조건·입력 | token·tenant·scope와 신뢰 경계, v1/v2 DB·스키마·freshness 관계, 외부 효과 |
| 결과·출력 | 실행·비교의 전제와 shadow·복귀 가능한 범위 |
| 실패·제한 | 비교 결과 일치를 위한 권한 확대 금지, 읽기 프록시의 쓰기 동기화·원자적 dual-write·데이터 복구 책임 제외 |

## 데이터·업무 책임 경계

| 관계 | 프록시 책임 | 서비스·데이터 계층 책임 |
| --- | --- | --- |
| 같은 DB를 읽는 v1/v2 | 요청 문맥 보존, 결과·지연 비교 | 쿼리·스키마·권한 호환, 공유 DB 부하 |
| 독립 DB를 읽는 v1/v2 | 비교에 필요한 source·freshness 문맥 기록 | 초기 적재·변경분·삭제·순서·오류 복구 |
| v1 쓰기 후 v2 읽기 | 읽기 관측과 전환 | v2 반영 시점과 read-after-write 요구 충족 |
| v2 전용 데이터·필드 사용 | 복귀 불가 사유를 전환 판단에 반영 | v1 호환 표현·변환·복원 계약 |
| 외부 시스템 호출 | shadow 여부·실행 결과 관측 | 외부 효과 차단, sandbox·quota·중복 비용 계약 |

- 쓰기 확장 검토의 선행 계약: authoritative source, 성공 ACK 조건, stable operation ID, 멱등 범위, 순서, 부분 성공, timeout 후 상태 불명, 재시도·재생·보존, 복구 소유자
- 두 API의 순차 호출·양쪽 성공 확인과 원자적 처리의 구분

- 환경·저장소·외부 제공자가 다른 경우 idempotency key의 중복 방지 영역 공유 여부 별도 확인
- 결제·알림 등 실제 효과의 제어 계약을 JSON 비교보다 먼저 확인
- 초기 프록시 구현의 쓰기 동기화 기능 추가 제외

## 비교·전환 전 데이터 준비 확인

| 확인 항목 | 담당 서비스의 제출 증거 | 미충족 시 처리 |
| --- | --- | --- |
| 데이터 원천 | authoritative source와 v1/v2의 논리 데이터 범위·세대 관계 | 문맥 불명 상태로 분류, 데이터 정합성 통과 판정 금지 |
| 초기 적재·변경분 | 초기 적재 기준점, 변경분 checkpoint·지연, 미해결 실패·삭제 반영 결과 | worker 종료만으로 데이터 준비 완료 표시 금지 |
| 읽기 가시성 | API 성공과 실제 조회 반영 시점, 필요한 read-after-write 조건 | 허용 시차·업무 불변식 위반을 전환 gate에 반영 |
| 데이터 검증 | 범위별 개수·ID·업무 필드·삭제 표본, 검증 범위와 한계 | 응답 표본 일치만으로 전체 데이터 무결성 보장 금지 |
| v1 복귀 | v2 쓰기 결과·스키마의 v1 해석 가능성, 동기화 유지·로그 보존 기간 | v1 프로세스 생존만으로 복귀 ready 표시 금지 |

- 동일 DB 사용 시에도 요청 시점·transaction 관점·배포 스키마 차이 확인
- 독립 DB의 내부 checkpoint 숫자끼리 직접 동등 비교 금지; 같은 원본 기준과 의미 확인
- 데이터 준비 증거의 소유자: 해당 서비스·데이터 파이프라인 담당자
- 프록시의 역할: 준비 상태·문맥을 비교·전환 판단에 반영; 동기화 엔진 구현 제외

## 접근·인증·본문 보호

- 목적지: 운영자가 등록한 backend로 제한; 요청 URL·헤더를 통한 임의 호스트 지정 금지
- 호출자 신원 검증 경계·신뢰할 forwarded header 정의; 인증 담당 위치는 기존 구조에 맞춰 결정
- v1 토큰의 v2 audience·scope·tenant 의미 검증; 비교 일치를 위한 권한 확대 금지
- backend 인증서 검증 유지, credential은 기존 비밀 관리 방식으로 공급
- 저장소 계정·조회 권한과 요청 실행 권한 분리, 필요한 범위만 부여
- 일반 로그·trace·exception·diff에도 동일 수집 정책 적용, 운영 원문·인증 정보 노출 방지
- 압축 해제·JSON 파싱·마스킹 실패를 자원 제한·드롭 사유에 포함

- 적용 범위: 프록시가 실제 처리하는 요청·관측 데이터의 경계
- 별도 보안 플랫폼·권한 관리 제품 구축 제외
