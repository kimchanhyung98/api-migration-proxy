# API Migration Proxy 공통 용어

이 문서는 API 전환에서 사용하는 이름, 실행 단위, 설정 식별자와 완료 상태를 정의한다. 같은 개념에는 같은 용어를 사용한다. 대상 API별 설정값과 운영 임계값은 해당 기능 문서에서 정의한다.

## Backend의 이름과 실행 역할

| 용어 | 정의 | 구분해야 할 대상 |
| --- | --- | --- |
| **v1 / v2** | v1은 전환 전 API backend이고, v2는 전환 대상 API backend이다. | 공개 URL의 버전 문자열이나 개별 배포 revision과 별개의 이름이다. v2를 serving으로 선택해도 이름을 v1으로 바꾸지 않는다. |
| **Serving** | 한 논리 요청에서 사용자에게 전달할 응답을 제공하도록 선택된 backend 역할이다. 프록시는 backend 실행 전에 serving을 선택한다. | v1 또는 v2가 맡을 수 있다. 먼저 성공한 backend를 뜻하지 않는다. |
| **Shadow** | 같은 논리 요청을 실행하지만 사용자 응답의 제공자로 선택되지 않은 반대편 backend 역할이다. 적격성·표본·자원 조건을 충족한 경우에만 실행한다. | v2가 serving이면 v1이 shadow 후보이다. Shadow는 요청 로그를 복사하는 행위가 아니라 backend를 실제 호출하는 행위이다. |

Shadow를 실행하는 경우 backend와 역할의 대응은 다음과 같다. Shadow가 선택되지 않았거나 실행 조건을 충족하지 못한 경우에는 반대편 backend를 실행하지 않는다.

| 선택한 serving | Shadow를 실행할 backend | 사용자 응답의 제공자 |
| --- | --- | --- |
| v1 | v2 | v1 |
| v2 | v1 | v2 |

Serving의 실패를 shadow의 성공으로 대체하는 것은 기본 처리에 포함되지 않는다. 그 동작은 아래에서 정의하는 fallback에 해당한다.

## 요청 식별과 배정 단위

| 용어 | 정의 | 판독 기준 |
| --- | --- | --- |
| **Route** | HTTP method, 경로의 의미와 공개 API 계약을 함께 등록한 API 단위이다. 공개 계약에는 입력·응답·인증·권한 조건이 포함된다. | 개별 raw URL과 같지 않다. 경로 변수 값이 달라도 같은 등록 route에 대응할 수 있다. Route 등록만으로 shadow 실행이 허용되는 것은 아니다. |
| **Cohort** | 같은 배정 기준에 따라 serving을 결정하는 사용자·세션·테넌트 등의 집합이다. | Cohort의 배정 비율과 실제 요청 수의 비율은 다를 수 있다. 각 집단이 보내는 요청 수가 같다는 보장은 없다. |
| **Cohort group** | Serving 배정의 일관성을 공유해야 하는 관련 route의 집합이다. | 관련 route 사이에 같은 배정 기준을 적용하기 위한 단위이다. 모든 route를 반드시 하나의 group으로 묶어야 한다는 뜻은 아니다. |
| **Logical request** | 호출자가 프록시에 보낸 요청 한 건이다. | 양쪽 backend가 실행되어도 논리 요청은 한 건이다. |
| **Backend attempt** | 하나의 논리 요청에 대해 특정 backend를 실행한 한 번의 시도이다. | Serving과 shadow가 모두 실행되면 두 번의 backend attempt가 발생한다. 실행 시도 수를 논리 요청 수로 표시해서는 안 된다. |
| **Comparison event** | 비교 수집 대상으로 선택된 논리 요청의 backend 실행 결과, 비교 판정과 해석 문맥을 묶은 관측 기록이다. | 성공하거나 일치한 응답만 기록하는 로그가 아니다. 전체 사용자 요청을 빠짐없이 기록한 메트릭도 아니다. 이벤트 생성과 저장 확인은 서로 다른 상태이다. |

Backend 실행 여부와 비교 상태의 구체적인 판정은 [비교 문맥과 결과](../comparison/context-and-outcomes.md)를 따른다. 비교 대상 응답을 메모리에서 확보하는 capture와 저장용 상세 데이터인 detail의 범위는 [상세 표본과 보호](../collection/detail-sampling.md)에서 구분한다.

## 계측·수집·노출의 구분

| 용어 | 정의 | 구분해야 할 대상 |
| --- | --- | --- |
| **내부 메트릭** | 프록시가 메모리에서 집계하는 횟수, 지연 분포와 현재 상태값이다. | 내부 계측은 항상 수행하며 HTTP 조회나 외부 서비스 연결을 전제로 하지 않는다. 현재 누적값은 프로세스 재시작 때 초기화된다. |
| **이벤트 수집기** | 프록시 내부에서 비교 이벤트의 큐, 배치, 저장 확인과 재시도를 처리하는 구성 요소이다. | 별도 서버에 설치하는 외부 메트릭 수집기와 다르다. |
| **이벤트 요약** | 허용된 실행·비교 결과와 해석 문맥을 남긴 기록이다. | 원문을 제거해도 식별자와 시각 등의 상관 정보가 남으므로 익명 정보라고 간주해서는 안 된다. |
| **SQLite 이벤트 저장소** | 선택된 shadow 비교 이벤트와 허용된 상세 표본을 저장하는 현재 저장 구현이다. | 개별 HTTP status와 지연 값이 있어도 전체 요청의 집계 지표 DB는 아니다. 이벤트만으로 전체 분모를 복원할 수 없다. |
| **메트릭 snapshot** | 특정 시점의 프로세스 내부 메트릭을 묶은 값이다. | HTTP endpoint나 메트릭 조회 CLI를 뜻하지 않는다. 여러 프로세스의 통합·영속 집계와도 구분한다. |
| **내부 상태** | `observation_status()`로 확인하는 현재 프로세스의 작업·수집 상태이다. | 내부 인터페이스이며 `/state` HTTP API로 제공하지 않는다. |
| **외부 관측 전송** | 관측 데이터를 외부 수집기나 서비스로 보내는 동작이다. | 현재 프록시는 해당 SDK나 exporter를 연결하지 않는다. 선택한 이벤트 저장소에 기록하는 동작과 구분한다. |
| **Health** | 전용 loopback listener의 `GET /healthcheck`에서 새 요청 수용 여부를 확인하는 기능이다. | 준비 상태이면 200과 `{"ready":true}`, 그렇지 않으면 503과 `{"ready":false}`만 반환한다. 별칭을 제공하지 않으며 backend·저장소의 정상 동작을 보장하지 않는다. |

관측 HTTP 조회나 이를 켜는 설정은 제공하지 않는다. Health의 바인드 주소와 실제 접속 peer는 모두 loopback으로 제한하며, 인증 token으로 이 제한을 해제할 수 없다. 내부 route와 트래픽 규모를 나타내는 메트릭도 보호 대상이다. 데이터의 조회·기록·전송 기준은 [인증·권한과 데이터 책임](identity-and-data-boundaries.md)을 따른다.

## 서로 독립적인 비율

| 값 | 조정하는 대상 | 조정하지 않는 대상 |
| --- | --- | --- |
| `v2_serve_ratio` | Serving 배정 대상 중 v2를 선택하는 비율을 정한다. 실제 배정 단위와 키는 route의 cohort 정책을 따른다. | Shadow 실행 비율이나 상세 데이터 저장 비율을 정하지 않는다. |
| `shadow_sample_ratio` | Shadow 적격 요청 중 표본으로 선택하는 비율을 정한다. 표본으로 선택되어도 자원 상한이나 중지 상태 때문에 실행하지 못할 수 있다. | 사용자에게 노출하는 v2 응답 비율을 정하지 않는다. |
| `detail_sample_ratio` | 상세 저장 정책의 대상 중 상세 데이터를 선택하는 비율을 정한다. 선택 이후에도 허용 필드·크기·마스킹·저장 제한을 적용한다. | Backend 실행 비율이나 비교 결과의 일치율을 정하지 않는다. |

세 비율은 목적과 분모가 다르다. 한 비율을 다른 비율의 실행 완료율 또는 저장 성공률로 해석해서는 안 된다. 실행·비교·저장의 단계별 분모는 [커버리지와 분석](../observability/coverage-and-analysis.md)을 따른다.

## 설정과 관측 구간

| 용어 | 정의 | 구분해야 할 대상 |
| --- | --- | --- |
| **Configuration revision** | 요청의 목적지, 배정, 실행과 수집 정책을 담은 설정 snapshot의 식별자이다. | Backend의 배포 revision과 다르다. 변경을 요청한 revision과 worker가 실제 적용한 revision도 구분한다. |
| **Comparison policy revision** | 비교 대상, 허용 차이와 제외 규칙의 의미를 식별하는 정책 버전이다. | Configuration revision과 항상 같은 값일 필요는 없다. 같은 backend 응답도 비교 정책이 달라지면 판정이 달라질 수 있다. |
| **Stage** | 기준선 관측, shadow 관측, canary, 전체 전환과 종료처럼 전환 목적과 통과 조건으로 구분한 운영 단계이다. | 배포가 끝났다는 이유만으로 다음 stage에 도달한 것으로 판단해서는 안 된다. |
| **Epoch** | 같은 설정과 관측 조건 아래의 결과를 함께 해석하는 관측 구간이다. | 서로 다른 revision이나 문맥의 표본을 조건 확인 없이 합산해서는 안 된다. Epoch의 범위와 분리 조건은 [단계와 gate](../rollout/stages-and-gates.md)를 따른다. |
| **Gate** | 다음 전환 단계로 진행할 수 있는지 판단하기 위해 충족해야 하는 조건의 집합이다. | 단일 비교 결과나 설정 제출 성공을 뜻하지 않는다. 필요한 증거와 미충족 시 처리는 해당 단계의 gate에서 정한다. |

## 변경·복구 동작

| 용어 | 정의 | 해당 동작만으로 완료되지 않는 작업 |
| --- | --- | --- |
| **Fallback** | 개별 요청의 실패에 대응하여 다른 backend에서 사용자 응답을 얻으려는 동작이다. | 전체 serving 비율을 되돌리는 rollback과 다르다. 기본 모델에서는 자동 fallback을 수행하지 않는다. |
| **Rollback** | 이후 요청의 serving 배정을 이전 운영 상태로 되돌리는 설정 변경이다. | 이미 처리한 요청의 취소, 데이터 복원 또는 외부 효과의 취소를 포함하지 않는다. |
| **Shadow 중지** | 이후 요청에 대해 반대편 backend의 shadow 실행을 막는 조치이다. | Serving 배정 변경이나 진행 중인 모든 작업의 즉시 취소를 뜻하지 않는다. 적용 범위는 [수명과 제한](../shadow/lifecycle-and-limits.md)을 따른다. |
| **프록시 우회** | 호출자의 요청이 프록시를 거치지 않는 경로를 사용하도록 진입 경로를 변경하는 조치이다. | 프록시 내부의 serving 비율 변경과 다르다. 우회 경로의 인증·전달 계약을 별도로 확인해야 한다. |

## 상태를 읽는 기준

- `미정`은 값을 아직 결정하지 않았다는 뜻이다. `미확인`은 판단할 사실이나 증거를 확보하지 못했다는 뜻이다.
- 값 `0`은 해당 범위와 구간에서 측정하거나 확인한 값이 0이라는 뜻이다. 관측 누락을 `0`으로 바꾸어서는 안 된다.
- 실행하지 않은 요청, 실행했으나 실패한 요청, 비교할 수 없는 결과와 저장을 확인하지 못한 이벤트는 서로 다른 상태이다. 각 상태에는 해당 기능에서 정의한 사유를 남겨야 한다.
- `완료`는 반드시 완료한 작업을 함께 적는다. 요청 실행, 비교 판정, 저장 확인, 설정 전파, 전환과 데이터 복구의 완료를 서로 대신 사용해서는 안 된다.
