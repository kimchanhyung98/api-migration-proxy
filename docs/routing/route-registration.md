# API 경로 등록과 지원 범위

- 목적: 마이그레이션 대상 요청 식별 및 일치하는 route·고정 목적지 결정

## 기능 계약

| 항목 | 정의 |
| --- | --- |
| 시작 조건·입력 | method·path template, route ID, v1/v2 목적지, 전환 활성 여부, API 계약과 소유자 |
| 결과·출력 | 하나의 등록 route 또는 명시된 v1 통과·기존 진입점 처리 결과 |
| 실패·제한 | 중복·모호한 우선순위·잘못된 목적지의 활성화 전 거부; 미지원 프로토콜의 투명 전달 보장 제외 |

## 등록할 정보

| 정보 | 작성 기준 |
| --- | --- |
| route ID | raw URL과 독립된 안정적인 식별자 |
| method·path template | 허용 method와 동적 경로 구간을 명확히 정의 |
| v1/v2 목적지 | 운영자가 지정한 고정 backend; 호출자 입력으로 임의 호스트 선택 불가 |
| API 계약 | 정상·예상 거절·업무 오류, 헤더·body와 인증·권한 의미, 지원 콘텐츠 형식·본문 크기 범위 |
| 실행 적격성 | 실제 업무 효과의 검토 결과; 등록만으로 shadow 허용하지 않음 |
| 소유자 | 대상 API와 전환 조건을 확인할 담당 역할 |

## 등록과 검증 흐름

1. 첫 API의 method·path·입출력 예시와 호출자 정리
2. route ID·v1/v2 목적지 정의 및 필요한 경우에만 좁은 path 매핑 추가
3. 중복 route·wildcard·template 충돌 검사 및 미정 우선순위의 자동 추정 금지
4. 입력·응답 계약, 권한과 부작용 검토 결과 연결
5. 필수값·운영 한도·지원 범위 검증 후 전환 활성화

## 미등록·미지원 요청

- 검증된 일반 HTTP 경로: 기본 v1 통과 유지
- SSE·WebSocket·gRPC·대용량 전송 등 지원 미검증 경로: 기존 진입점 유지
- route 제거·비활성화: 기존 호출 경로 유지 여부 검증
- 등록 경로 일부의 v2 전환: 서비스 전체 전환 완료와 구분
- 전환 종료: 미등록·미지원 v1 의존 재확인

## 요구사항과 수용 조건

| ID | 우선순위 | 요구사항 | 수용 조건 |
| --- | --- | --- | --- |
| FR-01 | P0 | method·path template으로 route와 고정된 v1/v2 목적지 등록 | 모호한 우선순위·중복 route·잘못된 목적지는 활성화 전에 거부 |
| FR-08 | P0 | 미등록·미지원 경로 처리 방식 명시 | 검증된 일반 HTTP는 기본 v1 통과, 미지원 프로토콜은 기존 경로 유지 |
