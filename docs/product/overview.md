# 제품 개요와 도메인 경계

- API Migration Proxy: 기존·신규 API를 관측하며 사용자 응답을 점진적으로 전환하는 임시 프록시
- 문서 범위: 제품 전체의 목적·책임·성공 기준

## 제품 방향과 결정 상태

| 항목 | 내용 |
| --- | --- |
| 상태 | 현행 공식 기능 기획; API 구현과 운영 검증 전 |
| 확정된 방향 | 단순한 API 마이그레이션 프록시, v1/v2 양쪽 요청과 데이터 수집, 메트릭, 점진적 전환 |
| 배경 | Elasticsearch 클러스터 마이그레이션의 요청 분기·응답 선택·관측 방식을 일반 API에 적용 |
| 기술 후보 | AWS, FastAPI, PostgreSQL. 구체 제품·버전·구성은 미선정 |
| 초기 범위 | 제한된 수의 부작용 없는 HTTP JSON API |
| 운영값 | 대상 경로, QPS, timeout, 표본율, 보존 기간, SLO와 승격 기준 모두 결정 필요 |

- 상세 설계·운영 수치: 대상 API의 계약·대표 부하·운영 조건을 확인한 뒤 확정
- 문서의 예시 수치: 설명용 값, 운영 기본값으로 사용 금지

## 문제 정의

- 변경 대상: API 구현체·프레임워크·서비스 경계·실행 인프라
- 사전 테스트의 한계: 제한된 입력만으로 실제 권한·데이터 상태·피크 부하 재현 곤란
- 일괄 전환의 위험: 사용자 노출 이후 특정 조건의 차이 발견
- 단순 트래픽 분산의 한계: 동일 요청에 대한 기존·신규 결과의 직접 비교 곤란
- 단순 요청 복제의 한계: 응답·실패 수집이 없으면 실행 여부만 확인 가능
- 해결 방향: 요청 분기 → 양쪽 결과 수집·비교 → 관측 기반 점진적 전환

## 제품 목표

1. 호출자 변경을 제한하는 v1/v2 공통 진입점 제공
2. 동일 요청의 상태 코드·응답 계약·지연·실패 연계를 통한 조사 시간 단축
3. 사용자에게 노출할 v2 응답 비율의 독립 조정
4. 비교 실패·수집 누락 공개 및 근거 없는 승격 방지
5. 장애 위치에 따른 shadow 중지·v1 복귀·프록시 우회 구분
6. 종료 후 제거 가능한 운영 구성과 최소한의 업무 로직 의존 유지

- 성능·가용성·지원 범위: 실제 목표값과 환경을 정한 뒤 검증
- 무조건적 무중단·추가 지연 없음·전체 HTTP 지원·데이터 완전 일치 보장 제외

## Elasticsearch 마이그레이션에서 가져오는 원리

- 적용 원리: 기존·신규 대상의 실행을 유지하며 사용자 응답 선택만 단계적으로 전환
- 데이터 준비: 배치·변경분 동기화와 읽기 검증의 책임 구분
- 쓰기 API 복제: ACK·내구 기록·재처리 계약을 정한 뒤 별도 검토

| 클러스터 마이그레이션 관점 | API 마이그레이션에서의 의미 |
| --- | --- |
| old/new 클러스터 | v1/v2 API 구현체 또는 배포 대상 |
| 배치·스트리밍 쓰기의 양쪽 반영 | 독립 데이터 저장소의 초기 적재·지속 동기화 계약 확인; API 쓰기 복제는 별도 검토 |
| 양쪽 검색 실행 | 복제 가능한 동일 요청의 양쪽 실행 |
| 사용자별 응답 선택 | 안정적인 cohort 또는 무상태 요청 단위 serving 배정 |
| 데이터·성능 관측 | API 계약 차이, 실행 오류, 사용자 지연, 데이터 문맥 관측 |
| old로 되돌릴 준비 | v1의 데이터·스키마·권한·용량 유지 |
| old 검색 중단과 리소스 종료 | v1 shadow 종료, 호출자 정리, 프록시 제거를 별도 단계로 수행 |

- 기본 모델 제외: 검색 순위·점수·샤드·인덱스 세대 등 Elasticsearch 전용 개념
- 업무별 비교 확장: 실제 대상 API에서 필요한 경우에만 추가 검토
- 초기 읽기 중심 범위: 단순성과 업무 효과의 통제를 위한 적용 기준
- 결제·알림·예약 등 쓰기 확장: [권한·데이터 책임](../_rules/identity-and-data-boundaries.md)의 선행 계약 확인 후 별도 결정
- 프록시 제거: 직접 v2 경로와 복귀 조건을 검증한 뒤 진행할 제품 종료 설계
- 실행·관측·전환 원리: [Elasticsearch 방식의 API 적용](../research/elasticsearch-reference.md)
- 리팩토링·전환 패턴 근거: [API 마이그레이션 적용 경계](../research/refactoring-and-migration.md)

## 사용자와 책임

| 사용자 | 필요한 결과 | 주 책임 |
| --- | --- | --- |
| API 개발자 | 어떤 입력과 조건에서 v1/v2가 다른지 확인 | 공개 계약, 부작용, 성공·오류와 비교 정책 정의 |
| 마이그레이션 담당자 | 다음 전환 비율을 결정할 수 있는 증거 | 단계 변경, 관측 구간, 결과 기록과 종료 |
| 운영 담당자 | 프록시와 shadow가 서비스에 미치는 영향 확인 | 자원 한도, 배포, 알림, 장애 복구와 우회 |
| 데이터 담당자 | 데이터 시차와 구현 차이를 구분 | 독립 DB 동기화, 최신성·스키마와 롤백 데이터 계약 |
| 서비스 책임자 | 실제 사용자 경험과 업무 영향 확인 | 허용 회귀, 중요 불변식, 사용자 지표 판단 |

- 한 사람이 여러 역할을 겸하는 구성 허용
- 역할 구분만으로 별도 시스템·조직을 요구하지 않음
- 대상 API별 연락 가능한 소유자 한 명 이상 지정

## 성공 지표

| 성공 관점 | 판단 근거 |
| --- | --- |
| 기능 | 대상 route에서 양쪽 요청과 선택된 응답 전달이 계약대로 동작 |
| 품질 | 사전에 정한 응답 차이·오류·지연 기준 충족 |
| 관측 | 표본·비교 완료율·유실이 기준을 만족하며 주요 차이의 원인 추적 가능 |
| 운영 | 실제 설정 적용과 v1 복귀·프록시 우회 시간을 검증 |
| 비용 | shadow·수집으로 생긴 추가 부하가 정한 예산 안에 있음 |
| 종료 | v1 잔존 호출과 프록시 의존을 정리하고 직접 v2 호출을 검증 |

- 지표 목표값: [품질 요구사항](../validation/quality-and-acceptance.md)에 따라 실제 대상 환경에서 확정
- QPS·비율·지연·비용 목표: 실제 대상 API의 기준선과 운영 예산을 바탕으로 결정

## 전체 사용 흐름

```mermaid
flowchart LR
    A[대상 API와 계약 등록] --> B[v1 통과와 기준선 확인]
    B --> C[v2 shadow와 양쪽 결과 수집]
    C --> D[차이와 누락 원인 확인]
    D --> E[일부 사용자에게 v2 응답]
    E --> F[전체 v2 응답과 복귀 기간 유지]
    F --> G[v1 shadow 종료와 프록시 제거]
    E -. 악화 시 .-> B
    F -. 복귀 조건 충족 시 .-> B
```

- 사용자 응답 비율과 shadow 실행 비율의 독립 제어
- 양쪽 실행 유지 시: v2 응답 비율 100%에서도 v1 요청 발생 가능
- 양쪽 성공·일치와 데이터 정합성·사용자 경험·운영 전환 성공의 별도 판단

## 도메인 경계

| 영역 | 소유하는 판단 | 다음 영역으로 넘기는 결과 |
| --- | --- | --- |
| 요청 라우팅 | 어떤 route·설정·serving을 사용할지 | 고정된 실행 계획과 사용자 응답 경로 |
| shadow 실행 | 반대편 실행 가능성·표본·수명 | v1/v2의 개별 실행 종료 결과 |
| 응답 비교 | 어떤 조건에서 같은 결과로 볼지 | 비교 상태·이유·제한된 차이 |
| 데이터 수집 | 무엇을 기록·조회·보존할지 | 저장된 고유 이벤트와 수집 상태 |
| 관측 | 실행·비교·저장의 분모와 지연을 어떻게 해석할지 | 사용자·검증·수집 품질의 증거 |
| 전환 관리 | 다음 비율로 확대·복귀·종료할지 | 새 단계와 설정 변경 의도 |
| 인프라 | 공통 권한·데이터 기준에 맞춰 실행 환경·자원을 어떻게 배치할지 | 운영 제약과 용량·복구 조건 |
| 검증 | 어떤 순서와 증거로 완료를 판단할지 | 요구사항별 검증 결과와 미확인 범위 |

- 도메인 구분: 문서와 책임의 경계, 별도 배포 서비스 구현을 강제하지 않음
- 초기 실행·비교·수집: 같은 프록시 서비스 안에 배치 가능
- 공통 기준: [공통 용어](../_rules/glossary.md), [권한·데이터 책임](../_rules/identity-and-data-boundaries.md)
- 도메인별 상세 기능: [문서 목록](../README.md)
